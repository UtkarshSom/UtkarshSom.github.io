One template, many emails.

Personalisation sounds like a big platform feature. Most of it is data, a few merge tags and a couple of conditions.

Utkarsh Som20 Oct 20265 min readEmail · Personalisation

When I started in CRM I thought personalisation meant buying something. A tool, a model, a vendor. It turned out the core of it is much plainer. You write one email in HTML, leave gaps where the content should change, and fill those gaps from data you already have.

That only works because the email is real code. If it's one flat image, there's nowhere to put a name or a price. This is the follow-up to my post on images versus HTML, and it's the part I find most useful day to day.

Start with what you know

You don't need much. A first name, the country or currency, the language, the last thing they looked at, what's in their basket and which segment they sit in will carry a lot of emails. Every one of those can be missing for someone, so every one needs a fallback. More on that below.

Here is a small template filled four different ways. Switch the reader, then flip the switch to send everyone the same email. The highlighted bits came from the data.

Three moves do most of it

1. Merge tags with a fallback. A tag drops a value into the text. Always say what to show when the value is empty, or you'll send "Hi ," to someone. Try the "No data" reader above. The syntax changes between platforms, so treat these snippets as the idea.

Hi {{ first_name | default: "there" }},

2. Conditional blocks. Show a block only when it applies. Sarah has a basket, so she gets a nudge about it. Omar doesn't, so he gets something new instead.

{% if cart.items %}
  {{ cart.items[0].name }} is still in your basket.
{% else %}
  Picked for you, based on what you've looked at.
{% endif %}

3. Loops. Repeat a block for each item, so the same template can show one product or three.

{% for item in recommendations limit: 3 %}
  {{ item.name }}  {{ item.price }}
{% endfor %}

Language and currency work the same way. They're conditions on a field, and the price is a value from your catalogue. None of this is possible when the words and numbers are baked into a picture.

Where it goes wrong

  • Missing data. No fallback gives you "Hi ," or a broken sentence. Every tag needs a default.
  • Long values. Very long names or product titles can break a layout that looked fine with "Sarah". Test with a ridiculous one.
  • Empty loops. If a list has nothing in it, you can be left with a heading and a blank gap. Wrap the whole block in a condition.
  • Wrong currency or language. Check the price and the copy come from the same field. A German headline over a pound price is easy to ship by accident.
  • Images that can't change. If the offer is part of the picture, it can't follow the data. Keep the changing parts as text.

Before you send a personalised email

  • Every tag has a fallback.
  • Preview as someone with no data, and as someone with too much.
  • Every conditional block has an else, or is allowed to be empty.
  • Language, currency and price come from the same place.
  • Test a real profile from each segment.

You can start small. Add a first name with a fallback, then one condition, and test both. That's already more than a flat image can ever do.
